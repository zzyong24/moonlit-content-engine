# 用户审美与质量反馈台账（全形态共用，只增不删）

用户每次说“不够好 / 这里还要加 / 不是这个感觉 / 偷懒了”，除了修当前作品，还要把它写成一条**可检查的规则**追加到对应形态分区，并在当前作品里排查同类问题。各 Skill 开工前读取“通用”和本形态分区；交付说明写“已按反馈台账 Gx / Vx … 自检”。

工作区若提供 `maintenance/feedback-ledger.md` 或 `maintenance/quality-samples.json`，以工作区版本为准，本文件只保存可公开的通用规则；带个人原话、私人素材的条目只写进工作区。

格式：`编号｜日期｜用户原话摘要｜规则（可检查）｜检查方法`

## 文字（W）

- W1｜2026-10｜文字安全但平｜成稿前按 `moonlit-business-copywriter/references/writing-toolkit.md` 做一遍“加法”｜交付说明列出用了哪 2–3 招、改了哪几句
- W2｜2026-10-15｜作者给的是要点大纲（“我给的只是大纲，你去找材料写，并纠错”），助手却只做润色、不查证｜识别为“扩写纠错”模式：逐条找资料扩写，事实错误用 `[改]` 标出并附来源，观点与立场不改｜交付含纠错清单与来源表；检查脚本 `--mode expand` 通过
- W3｜2026-10-15｜作者要求“从营销学和传播学角度”写｜开头用作者亲历的反转故事，正文给可收藏的路线/清单，保留作者的鲜明立场句，结尾一句话总结｜交付说明写明用了哪些传播手法

- W4｜2026-10-15｜口播稿像讲课：“第一个岔口”“一句话总结”这类报幕｜用故事推进或观众疑问过渡；清单可编号，过渡不编号｜检查脚本“报幕”提示为 0
- W5｜2026-10-15｜助手在段尾加判词和安慰（“不丢人”“这就是很多人的误区”），有爹味｜不补判词；作者自己的判断放回具体场景里说｜检查脚本“说教”提示为 0
- W6｜2026-10-15｜带 `／` 的提词器稿读起来像切碎的书面语｜交付干净的朗读版和标注版两份；书面句改成聊天说法，依据放来源表｜朗读版无 `／` 和标记
- W7｜2026-10-15｜开头故事太干｜向作者要时间、钱、物件、情绪等真实细节，不替作者编｜细节逐条能对应作者原话或确认记录
- W8｜2026-10-15｜作者另找的改写版比助手版更好：助手先套规则、把出处念进口播、把画面概念写成报幕、照抄对标结构不学语气｜先讲后改：先按作者语气写能念的初稿，再查事实（依据只进来源表），最后过检查；画面方案只进 `[画面]`；看对标先听语气｜交付前朗读一遍，无出处念白、无画面报幕
- W9｜2026-10-15｜工具箱的“短句”“钉子句”被用成判词金句｜短句只放事实或动作；钉子句只取作者原话、每篇最多一句、放回场景｜成稿中钉子句可对应作者原话
